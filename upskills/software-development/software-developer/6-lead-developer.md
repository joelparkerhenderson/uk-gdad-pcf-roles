# Lead developer - upskill resources

This page focuses on learning and growth resources for the work role of lead developer.

- The resources include links to online courses, blogs, research articles, videos, and books.

- These help with job upskilling, work training, professional development, and career advancement.

- These are intended to be good starting points, not a comprehensive catalogue.

At this role level you lead the technical work of a team, set direction, and take accountability for the health of the codebase and delivery pipeline. The resources below emphasise technical leadership, standards and sustainable delivery.

We welcome constructive feedback to improve this page and these lists.

- GitHub issues and/or pull requests are welcome.

- The resources are found via AI searches then go through human-in-the-loop proofing.

- For more contact Joel Henderson <joel@joelparkerhenderson.com>

## Coursera courses

- [Strategic Leadership: Impact, Change, and Decision-Making](https://www.coursera.org/specializations/strategic-leadership-impact-change-decision-making): A Dartmouth Tuck specialisation with Sydney Finkelstein covering the mistakes smart executives make, the neuroscience behind effective decision making, and how to manage and support the people around you.

- [Strategic Leadership: Influence and Thought Leadership](https://www.coursera.org/learn/strategic-leadership-influence-thought-leadership): Covers high-level influence techniques used by senior leaders, including mapping influence networks, strong framing, building legitimacy through consistency, and leading meaning-making in uncertain or crisis moments.

- [Influencing the Organisation](https://www.coursera.org/learn/influencing-the-organisation-leading-within-and-beyond-the-organisation): Covers managing stakeholders and organisational politics while mobilising people, and aligning your mission with the organisation's purpose.

## Udemy courses

- [Ultimate Clean Code Masterclass](https://www.udemy.com/course/ultimate-clean-code-masterclass/): Focuses on the SOLID principles, recognising code smells and refactoring systematically, in a way that applies across languages.

- [Clean Code with Java: Learn Simple Design, Refactoring and TDD](https://www.udemy.com/course/java-clean-code-with-refactoring-and-tdd/): Covers simple design, refactoring and test-driven development through worked code examples rather than abstract principle.

- [Refactoring to Design Patterns by Example](https://www.udemy.com/course/refactoring-to-patterns/): Refactors an existing working application toward design patterns while preserving behaviour, which is far more realistic than green-field pattern application.

## Skillsoft courses

- [Courses for Clean Coding](https://www.skillsoft.com/channel/clean-coding-8575b9b6-5528-42d1-ba5c-0e4bf0700582): Covers the philosophies, principles and practices that make software more efficient and less error prone, starting from what clean code is and why it matters.

- [Courses for Agile for Software Development](https://www.skillsoft.com/journey/agile-for-software-development-43d01c60-e3ca-4e12-8d32-d3fc3a2a693a): A proficiency journey from Agile and Scrum awareness through best practice for requirements and design, into how Agile methods are implemented in development and testing.

- [Clean Coding Techniques: Introduction to SOLID](https://www.skillsoft.com/course/clean-coding-techniques-introduction-to-solid-b857f940-ecad-11e7-8181-d3c41c82a4f4): A focused treatment of the five SOLID principles with examples of each being followed and violated.

## edX courses

- [CS50's Introduction to Computer Science (HarvardX)](https://www.edx.org/learn/computer-science/harvard-university-cs50-s-introduction-to-computer-science): Eleven weeks of lectures, problem sets and a final project covering programming and problem solving from the ground up. The best available foundation for a self-taught developer.

- [CS50's Web Programming with Python and JavaScript (HarvardX)](https://www.edx.org/learn/web-development/harvard-university-cs50-s-web-programming-with-python-and-javascript): Picks up where CS50 finishes, going deeper into the design and implementation of web applications.

- [CS50's Introduction to Programming with Python (HarvardX)](https://www.edx.org/learn/python/harvard-university-cs50-s-introduction-to-programming-with-python): A focused Python course covering functions, variables, exceptions, testing, file input and output, and object-oriented programming.

## MIT OpenCourseWare courses

- [15.317 Organizational Leadership and Change](https://ocw.mit.edu/courses/15-317-organizational-leadership-and-change-summer-2009/): A Sloan course blending leadership theory and practice, in which participants reflect on prior leadership experience and apply the lessons to develop their capability further.

- [15.067 Competitive Decision-Making and Negotiation](https://ocw.mit.edu/courses/15-067-competitive-decision-making-and-negotiation-spring-2011/): Develops negotiation skill through integrative bargaining cases between two and more than two parties over multiple issues.

- [6.005 Elements of Software Construction](https://ocw.mit.edu/courses/6-005-elements-of-software-construction-fall-2008/): Covers specification, abstraction and testing. Worth revisiting so that your technical judgement stays sound as you spend more time leading and less time writing code.

## Blog posts

- [The benefits of coding in the open](https://gds.blog.gov.uk/2017/09/04/the-benefits-of-coding-in-the-open): The Government Digital Service on why new government source code is published under an open source licence, and what follows from the design principle that making things open makes things better.

- [11 barriers to coding in the open and how to overcome them](https://technology.blog.gov.uk/2018/11/05/11-barriers-to-coding-in-the-open-and-how-to-overcome-them/): Terence Eden on the objections raised in government organisations and how each is answered in practice.

- [Don't be afraid to code in the open: here's how to do it securely](https://technology.blog.gov.uk/2017/09/27/dont-be-afraid-to-code-in-the-open-heres-how-to-do-it-securely/): Addresses which subsets of code should be kept closed and how to work securely in public repositories.

- [Government Software Engineering Community Blog](https://software-engineering-in-government.github.io/): Covers accessibility, internationalisation, privacy and security considerations specific to government software engineering.

- [Learning to code at GDS](https://gds.blog.gov.uk/2019/07/18/learning-to-code-at-gds/): On making coding accessible within an organisation, covering skills development and routes into technical roles.

- [Technology in government: Open Standards](https://technology.blog.gov.uk/category/open-standards/): Covers how open standards are selected and applied across departments, which constrains and enables technical choices.

- [Technology in government: Open Source](https://technology.blog.gov.uk/category/open-source/): Posts on open source practice in UK government, including the cross-government API catalogue.

- [Building reliable data pipelines: a foundational approach](https://www.getdbt.com/blog/building-reliable-data-pipelines): Useful for developers whose services produce or consume analytical data, covering what reliability actually requires.

- [Architecture Fitness Functions](https://synchronium.github.io/software-architecture-wiki/concepts/fitness-functions.html): Explains automated, objective assessment of architecture characteristics, from unit tests and ArchUnit rules through to chaos engineering.

- [The Up-and-Running Guide to Architectural Fitness Functions](https://mikaelvesavuori.se/blog/2023-08-20_The-Up-and-Running-Guide-to-Architectural-Fitness-Function): A practical guide to writing fitness functions with concrete implementation examples.

## Research articles

- [The Effects of Continuous Integration on Software Development: a Systematic Literature Review](https://arxiv.org/pdf/2103.05451): Analyses 101 empirical studies across development activities, software process, quality assurance, integration patterns, defects and build patterns.

- [On the effects of continuous delivery on code quality: A case study in industry](https://www.sciencedirect.com/science/article/abs/pii/S0920548921000830): A twelve-month industrial case study of what adopting continuous delivery actually did to source code and product quality.

- [An Empirical Investigation of Relevant Changes and Automation Needs in Modern Code Review](https://link.springer.com/article/10.1007/s10664-020-09870-3): Identifies what reviewers actually attend to in modern code review, including continuous delivery and integration concerns.

- [Investigating the Impact of Continuous Integration Practices on the Productivity and Quality of Open-Source Projects](https://dl.acm.org/doi/10.1145/3544902.3546244): An empirical software engineering study measuring the effect of continuous integration adoption on real projects.

- [On the Need to Monitor Continuous Integration Practices: An Empirical Study](https://arxiv.org/pdf/2409.05101): Finds that adopting continuous integration tooling is not the same as practising continuous integration, and proposes what to monitor.

- [Enhancing Software Quality Through Automated Code Review Tools: An Empirical Synthesis Across CI/CD Pipelines](https://journal.idscipub.com/index.php/digitus/article/view/956): Synthesises evidence on how much automated review tooling actually improves quality and productivity.

- [Hidden Technical Debt in Machine Learning Systems](https://papers.neurips.cc/paper/5656-hidden-technical-debt-in-machine-learning-systems.pdf): Sculley and colleagues on the maintenance costs that accumulate in systems with data dependencies, increasingly relevant to ordinary services.

- [Identifying architectural technical debt, principal, and interest in microservices: A multiple-case study](https://www.sciencedirect.com/science/article/pii/S0164121221000650): Based on 25 practitioner interviews across seven large companies, identifying 16 architectural debt issues with their impact and repayment cost.

- [The technical debt gamble: A case study on technical debt in a large-scale industrial microservice architecture](https://www.sciencedirect.com/science/article/pii/S016412122500216X): A mixed-method study combining static analysis with developer focus groups and interviews with the lead architect.

- [Test Code Review in the Era of GitHub Actions: A Replication Study](https://arxiv.org/pdf/2603.15935): Examines how test code is reviewed differently from production code, and what that means for quality.

## Books on Amazon

- [Clean Code: A Handbook of Agile Software Craftsmanship](https://www.amazon.com/Clean-Code-Handbook-Software-Craftsmanship-ebook/dp/B0FPFZTZYY): By Robert C. Martin. The most widely read book on writing readable, maintainable code, worth reading critically rather than as scripture.

- [Refactoring: Improving the Design of Existing Code](https://www.amazon.com/Refactoring-Improving-Existing-Addison-Wesley-Signature-ebook/dp/B07LCM8RG2): By Martin Fowler. The reference catalogue of refactorings with the reasoning for each, and the discipline of changing structure without changing behaviour.

- [The Pragmatic Programmer: Your Journey to Mastery, 20th Anniversary Edition](https://www.amazon.com/Pragmatic-Programmer-journey-mastery-Anniversary-ebook/dp/B07VRS84D1): By David Thomas and Andrew Hunt. Broad practical advice on the craft, still the best single book for a developer building professional judgement.

- [Designing Data-Intensive Applications](https://www.amazon.com/Designing-Data-Intensive-Applications-Reliable-Maintainable-ebook/dp/B0GNTX59CY): By Martin Kleppmann and Chris Riccomini. Explains the trade-offs behind storage and processing technologies and the fundamentals of distributed systems.

- [Fundamentals of Software Architecture: A Modern Engineering Approach](https://www.amazon.com/Fundamentals-Software-Architecture-Engineering-Approach-ebook/dp/B0F1BWQGYZ): By Mark Richards and Neal Ford. Covers architecture characteristics, styles and trade-offs in a way that applies across technology stacks.

- [Continuous Delivery: Reliable Software Releases through Build, Test, and Deployment Automation](https://www.amazon.com/Continuous-Delivery-Deployment-Automation-Addison-Wesley-ebook/dp/B003YMNVC0): By Jez Humble and David Farley. The foundational text on deployment pipelines and the practices that make frequent release safe.

- [Test Driven Development: By Example](https://www.amazon.com/Test-Driven-Development-Kent-Beck-ebook/dp/B095SQ9WP4): By Kent Beck. The original and clearest account of the technique from the person who named it.

- [The Robert C. Martin Clean Code Collection](https://www.amazon.com/Robert-Martin-Clean-Code-Collection-ebook/dp/B00666M59G): Bundles Clean Code with The Clean Coder, covering both the technical and the professional sides of the craft.

- [Threat Modeling: Designing for Security](https://www.amazon.com/Threat-Modeling-Designing-Adam-Shostack-ebook/dp/B00IG71FAS): By Adam Shostack. The standard reference for building security into a design from the start, structured around four questions.

- [Software Architecture Design Patterns in Java](https://www.skillsoft.com/book/software-architecture-design-patterns-in-java-7d03a4b0-efa2-11e6-be4a-0242c0a80906): A detailed explanation of when, why and how to apply design patterns, with worked examples.

## Professional development tips

- Lead by setting direction and removing obstacles rather than by making the decisions yourself
- Take accountability for the health of the codebase and the pipeline as well as for delivery
- Build the team's ability to work without you, since that is the actual measure of leadership
- Manage the technical debt portfolio explicitly with the people who fund the work
- Recruit and develop deliberately, since team composition determines almost everything else
- Represent the engineering perspective in planning and governance forums
- Read widely outside your immediate stack so that your defaults stay under review
